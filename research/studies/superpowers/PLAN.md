## Main question

How do shared skill instructions, host-specific delivery/tool mappings, work artifacts and verification mechanisms compose into Superpowers' development methodology, and where do their guarantees stop?

Units are provisional research questions, not the target's final architecture. A unit may span sessions; a session may close more than one bounded unit. File count and token consumption are not completion criteria.

- Adopt gstack's source-grounded synthesis method without its subsystem taxonomy/conclusions.
- Replace the introductory linear workflow with the actual three-path contract.
- Split shared skill content from host-dependent delivery; distinguish successful envelopes from usable bootstrap.

### v0.2 — U01-B evidence-led refinement

- Selected-source matrix now separates description visibility, full-body delivery, invocation, tool mapping and re-entry. U01 can close within the method's explicit source boundary.
- File revision, module lifetime, session events and message arrays are separate research variables. OpenCode probes reproduced both intended cache behavior and failed semantic-health criteria; neither is generalized into product qualification.
- Tool mapping can change actor/context/task semantics, not merely names. Carry this question into U03/U04.
- Procedure re-entry versus work recovery provides the concrete transition into U02; it does not prove absence of continuity elsewhere.
- Preserve host-namespace/version uncertainty, remaining distribution references and independent behavioral-evaluation questions as Q09–Q12 in the new note. These do not silently become mandatory live-host campaigns.
- METHOD v0.1 and whole-study closure criteria are unchanged. This is plan refinement and sequencing, not method adoption/effectiveness validation.
