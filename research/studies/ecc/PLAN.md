## U11-D disposition — backlog coordination and consumption

**Q04e3a:** The original frontier → team routing/rebalancing → source acknowledgement → control history → actual consumer/observer criterion is answered by Note22 and the ledger.

Normal guards remain: opt-in daemon automation, priority-aware bounded selection, keeping saturated drain inputs unread, rereading rebalancing eligibility and moving only the selected lead's messages. New session task arguments provide an initial input; reuse provides a persisted inbox message. The native runtime does not automatically poll/acknowledge those handoffs, and the actual CLI inbox marks more incoming rows than its limited output may display. External host consumption is not assumed absent or complete.

A newly created child's unread companion handoff can make it another lead on a later pass. With no intervening acknowledgement and successful admission, the same extracted task can be forwarded to another child; per-team capacity is not a global depth or task-lineage termination bound. This is conditional source reasoning, not observed infinite process growth. Rebalancing's post-assignment marker lacks drain's routing-action guard; changed capacity between precheck and action can expose a separate consumed-without-routed case.

Forwarding, message/projection writes, old read markers and statistics are separate effects. Errors and competing snapshots can leave effects without current acknowledgement/summary. Cooloff is driven by retained deferred counts/streak and recovery timestamps, without an elapsed-time expiry. A zero-reroute cycle skips the dispatcher and leaves those controlling fields unchanged; fresh usable capacity need not be retried. A streak frozen below five need not trigger the escalation flag. Positive rebalance/recovery paths and their tests remain explicit.

CLI manager calls differ from daemon recorder/cooloff wrappers; pressure/health combine current inbox data and historical controller data, not accepted deliverables. Test bodies inspect messages/counts/callbacks, not live model uptake or persistent eventual recovery. They were NOT RUN. A metrics session-bridge was ruled out as the missing inbox consumer, not used to claim repository-wide absence.
