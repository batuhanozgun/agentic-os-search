# Cross-Ground Transition / Propagation — Research Plan

**Status:** ACTIVE PLAN  
**Date:** 2026-09-06  
**Parent:** accepted `Transition / Effect / Feedback`

## Objective

Bound cross-ground realized-change and propagation semantics without collapsing the child into:
- Environment Domain Dynamics;
- Information Dynamics;
- generic event/history tracking;
- Work workflow state;
- one distributed-systems consistency model;
- or architecture-specific mechanisms such as event sourcing, sagas, message buses or state machines.

## Passes

### P0 — Canonical/current evidence recovery
Recover parent promotion logic, sibling boundaries, accepted ground-local dynamics, prior Standing/Control invalidation findings, candidate-study pressure and authoritative holdout targets. Freeze falsifiers before synthesis.

### P1 — Minimum cross-ground transition signature
Test what a decision-critical cross-ground transition claim must preserve: exact changed focus, baseline/prior state or trajectory reference, realized change identity, relevant bindings, scope, effective/occurrence/reference time, propagation applicability and evidence separation.

### P2 — Realization / propagation / temporal-state discrimination
Attack collapses among requested, admitted/committed, initiated, realized, effective, propagated, observed and recorded change. Test whether one universal lifecycle exists or whether only non-collapse relations are Foundation-stable.

### P3 — Partiality / convergence / invalidation / recovery audit
Study partial application, delay, stale dependents, conflicting/superseding updates, convergence, persistent divergence, retry, rollback, compensation, reconciliation and residual effects. Preserve Work versus Transition ownership and Standing/Control invalidation boundaries.

### P4 — Rival internal decompositions
Test candidate splits such as:
- Realization / Propagation / Convergence;
- Transition Identity / Propagation Scope / Recovery;
- Local Effect / Distributed Effect / Invalidation;
- Forward Change / Reconciliation;
- Requested / Realized / Observed;
- Atomic / Partial / Compensated.

Promote none without distinct protected questions, failure families, evidence requirements and cross-domain recurrence.

### P5 — Authoritative external + candidate holdouts
Use independent traditions as hostile pressure, not taxonomy authority. Candidate targets include:
- W3C PROV generation/invalidation/activity timing;
- OpenTelemetry occurrence versus observation timing;
- AWS and Google Cloud IAM propagation/change effectiveness;
- distributed-systems ordering/convergence sources;
- systems/configuration-management change implementation and verification;
- institutional rule/effective-date or staged implementation examples where useful;
- candidate studies such as Anthropic AI-native SDLC and gstack only where source-grounded and freshness-bounded.

### P6 — Synthesis / immediate-child decision
Decide whether the child is a bounded leaf, needs immediate children, exposes a sibling correction or reopens parent/four-ground adequacy.

### P7 — Adversarial closure
Attack the strongest provisional result, especially:
- generic dynamics bucket risk;
- software/distributed-systems vocabulary leakage;
- false universal lifecycle stages;
- rollback/compensation/reconciliation confusion;
- stale Standing versus changed Standing collapse;
- event record versus actual occurrence collapse;
- under-promotion of convergence/invalidation;
- architecture/schema leakage.

## Required non-collapse probes

```text
change requested != change realized
change committed locally != change effective across scope
change realized != change observed
observation time != occurrence/effective time
partial propagation != full convergence
retry Work != successful propagated result
rollback attempt != restored prior reality
compensation != literal reversal
reconciliation Work != reconciled state
binding/dependency changed != prior standing automatically false
control revised != all enforcement points updated
recorded transition != actual transition by identity
```

## Closure criteria

Close only when:
- the protected question is coherent and irreducible;
- ground/sibling boundaries are stable;
- external/candidate holdouts do not expose a live first-order gap;
- rival decompositions fail or a justified child split survives;
- residuals are explicit reopen triggers rather than hidden execution debt;
- no architecture/schema commitment is required for the Foundation result.
