### M1 · Makine-okur iş kuyruğu + "sıradaki iş" betiği
- **Sorun:** *"'sıradaki iş' bilgisi düzyazıda ve danışmanın kafasında yaşıyordu"* (hafıza `feedback-durma-yasagi`); sohbette anlatılan plan bağlam temizlenince uçtu (Batu: *"yeni oturumda R1'i hatırlayacak mıydın?"*; dosyanın kaydı: "Cevap hayırdı.", `hafiza-aynasi/feedback-ortam-tek-seferlik-is-degil.md`).
- **Biçim** (`IS_KUYRUGU.md` başlığı): *"`KUYRUK|<kimlik>|<durum>|<engel>|<kabul ölçütü>|<işaretçi>` — altı alan, hiçbiri boş olamaz. durum: acik·calisiliyor·beklemede·ertelendi·bitti·iptal · engel: yok, bir kimlik ya da sebep"*; *"aynı anda birden çok calisiliyor bekçide kırmızıdır; beklemede/ertelendi sebebini engel alanında taşımak zorundadır. Havada iş kalmaz."*; *"Öncelik dosya sırasıdır"*; biten kalem en fazla 10 satır durur. Örnek: `KUYRUK|A13|acik|yok|yayın töreni ağaçta dört boş dizin bırakıyor ... Kabul: tören sonrası ağaç temiz VE bozması kırmızı|tools/yayin.sh`. Hat önekleri: `A` ortam arızası · `K` KEEL · `B` sahipte · `Z` izleme (zaman tetikli).
- **Betik** (`tools/sirada.sh`): önce `calisiliyor`, sonra engeli çözülmüş `acik` kalemi basar (`▶ kimlik`, `biter:`, `malzeme:`, `sonra:`); çıkış hep 0 (*"bu bir kapı değil, bir gösterge"*). Engel çözümü üç sonuçludur:
  ```bash
  engel_cozuldu() {
    # $1: engel alanı. ÜÇ SONUÇ döner — 0 çözülü · 1 gerçekten engelli · 2 ÇÖZÜLEMEDİ (biçim).
    # [satır 27–33: A14 gerekçe yorumu çıkarıldı]
    [ "$1" = "yok" ] && return 0
    case "$1" in sahip|zaman) return 1 ;; esac
    # Alanın HER jetonu bir kuyruk kimliği olmak zorunda; biri değilse alan çözülemedi.
    for k in $1; do
      case " $KIMLIKLER " in
        *" $k "*) case " $BITENLER " in *" $k "*) ;; *) return 1 ;; esac ;;
        *) return 2 ;;
      esac
    done
    return 0
  }
  ```
  Çözülemeyen alan her koşuda *"⚠ ENGELİ ÇÖZÜLEMEYEN KALEM"* başlığıyla basılır.
- **Denetim:** bekçi madde 7 (altı alan, boş alan, bilinmeyen durum, tek `calisiliyor`, sebepsiz `beklemede/ertelendi`, biten >10 SARI, "engeli kapanmış ama hâlâ engelli" bayat bağ) ve madde 9 (çalışma dosyası ↔ kuyruk üç yönde: kuyruksuz dosya · ölü işaretçi · biten kalemin dosyası canlı ağaçta).
- **Kanıt:** A14 (kaynak diyor): engel alanına düzyazı yazılınca K10 araca görünmez oldu ve betik *"'koşulabilir açık iş yok, kuyruğa yeni iş yazma zamanı' bastı — doğrunun TERSİ... Ölçemediğin engel, ölçülmüş engel değildir"*; düzeltmenin bozmaları 28a–28c (düzyazı engel görünür kalır · mutant üçüncü sonucu sökünce kalem yanlış sınıflanır · temiz engel sıraya girer).
- **DevOS: al ve yükselt.** Tek repolu bulut oturumunda SessionStart kancası yüklenir (brief); `compact` matcher'ı %80 sıkıştırmadan sonra sıradaki işi yeniden bastırır (çıkarım). Yükseltme: kalem satırına os-architect'in hiç ölçmediği iki alan eklenmeli: amaca bağ (hangi Batu hedefini ilerletiyor) ve süre/son hareket damgası (duvar saati); os-architect'in duran talimatı *"Sıra körü körüne koşulmaz"* (CLAUDE.md, 2026-08-07: *"yeni iş açmadan önce envanter·bağımlılık·sıra ayrı geçişte denetlenir"*; yol kararı D-39) yalnız talimattı; DevOS'ta sıranın kendisini ayrı geçişte denetleyen PM adımı kuyruğun mekanik parçası olmalı (ör. sıra değişikliği commit'i PM geçişinin izini taşımadan kapıdan geçmez).

### M9 · Commit çift çapası: PreToolUse kancası + git `commit-msg`
- **Sorun:** *"Açılış kancası (SessionStart) kırmızıyı yalnız EKRANA basar — hiçbir şeyi durduramaz, üstelik komutu `|| true` ile bitiyordu. Yani kuralın tek çapası danışmanın çıktıyı okuyup uymasıydı: denetlenen tarafın kendi disiplini."* (`commit-kapisi.sh`)
- **Nasıl:** `commit-kapisi.sh` stdin'deki kanca JSON'undan komutu alır, yalnız `git commit` desenine bakar, önce taşıma sayım kapısını, sonra bekçiyi koşturur (satır 97–124; yalnız boş satırlar çıkarıldı):
  ```bash
  # beyanlı istisna (yalnız bekçi kırmızısı içindir, yukarıdaki sayım kapısı için değil)
  printf '%s' "$komut" | grep -q 'KIRMIZI-ILE:' && exit 0
  sonuc="$("$kok/tools/bekci.sh" "$kok" 2>&1)" || true
  satir="$(printf '%s' "$sonuc" | grep '^BEKCI-SONUC' | tail -1)"
  # bekçi konuşmadıysa fail-closed: sessiz yeşil yok
  if [ -z "$satir" ]; then
    echo "commit-kapisi: bekçi sonuç satırı basmadı — fail-closed, commit engellendi." >&2
    exit 2
  fi
  durduran="$(printf '%s' "$satir" | sed -n 's/.*durduran=\([0-9]*\).*/\1/p')"
  ariza="$(printf '%s' "$satir" | sed -n 's/.*ariza=\([0-9]*\).*/\1/p')"
  [ -z "$durduran" ] && durduran=1
  [ -z "$ariza" ] && ariza=1
  if [ "$durduran" -gt 0 ] || [ "$ariza" -gt 0 ]; then
    {
      echo "commit-kapisi: BEKÇİ KIRMIZI — commit engellendi (durduran=$durduran ariza=$ariza)."
      echo "Kırmızı dururken yeni iş kaydedilmez. Önce kırmızıyı kapat:"
      printf '%s\n' "$sonuc" | grep -E '^KIRMIZI|^BEKCI-ARIZA' | sed 's/^/  /'
      echo "Zorunluysa gerekçeyi commit mesajına 'KIRMIZI-ILE: <sebep>' satırıyla yaz."
    } >&2
    exit 2
  fi
  exit 0
  ```
  Okunamayan sayı 1 sayılır (fail-closed); ret mesajı stderr ile modele döner.
  Beyanlı istisna: mesajda `KIRMIZI-ILE: <sebep>` (*"sessiz değil, git geçmişinde görünür"*). Taşıma kapanışında `giren=<n> cikan=<n> yok=<n>` zorunlu; *"Tetik BEYANA DEĞİL DURUM DEĞİŞİMİNE bağlıdır"* (kuyruk satırı bu commit'le `bitti`ye dönüyorsa); bu kapının istisnası yok. İlan edilmiş kör kip: *"`bekci.sh && git add -A && git commit …` biçimindeki tek çağrı, bekçi çağrının içinde kırmızıya döndüğü hâlde commit'i geçirdi"* → ikinci çapa `tools/git-hooks/commit-msg` (*"git'in KENDİ içinde, mesaj yazıldıktan ve ağaç son hâlini aldıktan SONRA koşar"*); bağlılığını (`git config core.hooksPath tools/git-hooks`) madde 11 ölçer, 24a–24d bozar.
- **Ek kör kip (kaynak diyor, `yayin.sh`):** commit'i betik içinden atan araç kapıyı atlar: *"`bash tools/yayin.sh v0.1` komutunda 'git commit' geçmediği için tören, kapının hiç görmediği bir yerden commit atardı"* → tören bekçiyi kendisi ön şart olarak koşturur.
- **DevOS: al ve yükselt.** Bulutta `core.hooksPath` yerel git ayarıdır, taze klonda yoktur → SessionStart kancasında idempotent kurulmalı, bekçi ölçmeli (çıkarım). Yükseltme: `KIRMIZI-ILE` kullanımı sayılmalı ve eşik aşılınca kapının kendisi incelemeye açılmalı (madde 23e dersi); push da aynı çapaya bağlanmalı.
